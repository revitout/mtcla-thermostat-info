MTCLA Thermostat Remote

Privacy policy

Effective November 15, 2026

Thermostat information is used to operate a dedicated controller at one church.

Purpose and scope

MTCLA Thermostat Remote is a private installation maintained for one church. This policy covers the physical controller, its local authorization and setup tools, and these public information pages.

Information accessed

With the account holder's authorization, the application accesses information about the selected Google Nest thermostat, including its device identifier, available operating modes, room temperature, target temperatures, connectivity, Eco state, and reported heating or cooling activity. During setup, the administrator can also see the names of authorized homes, rooms, and thermostats to choose the correct device.

The application uses an OAuth client identifier, client secret, refresh token, and temporary access tokens to maintain authorized API access. Google account sign-in takes place with Google; the controller does not request or store the account holder's Google password.

How information is used

Thermostat information is used to show current conditions and system status, make the relevant controls available, and check whether a requested change was accepted. Authorized operator actions send temperature or mode commands, including Off, to the selected thermostat through Google.

The application does not sell Google user data, use it for advertising, or create marketing profiles. Its use and transfer of information received from Google APIs adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Storage and retention

Integration configuration and refresh credentials are stored on the administrator's setup computer and in the controller's persistent storage until the administrator removes or replaces them. Temporary access tokens and working thermostat readings are held in runtime memory. Troubleshooting records may also contain device status and temperature readings and remain until deleted by the administrator.

The application does not maintain a thermostat history database. Connections to Google's API use HTTPS. The administrator is responsible for protecting the controller, setup computer, local files, and backups.

Sharing and public information

Google receives the authorization and API requests needed to read and control the thermostat and processes them under its own policies. Approved church operators can view the information shown on the controller, and the administrator can access local setup and troubleshooting records.

These public web pages contain application information and this policy. They have no thermostat connection, sign-in form, analytics code, or advertising code. Google credentials, device identifiers, live readings, Wi-Fi details, and backups are kept out of the website and its repository.

The pages are hosted on GitHub Pages. GitHub may record visitor IP addresses for security purposes, as described in GitHub's privacy statement. Questions submitted through GitHub Issues are publicly visible.

Removing access and deleting local data

The account holder can revoke the integration's permissions through Google Nest Partner Connections or the Google Account's connected-app settings. Revoking authorization stops future authorized API access. The church administrator can separately remove stored integration credentials and delete setup files, diagnostic records, and backups under their control. Revocation does not automatically delete those local copies.

Questions and changes

Contact the maintainer through the project's GitHub Issues page for application or privacy questions. People using the church installation can also contact the church's thermostat administrator directly. Keep private information out of public support requests.

This policy will be updated if the application's data practices change. The account holder will be informed before their Google data is used for a new purpose.
